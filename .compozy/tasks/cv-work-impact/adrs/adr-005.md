# ADR-005: Hard rename `/projects` → `/work` with no redirect

## Status

Accepted

## Date

2026-06-10

## Context

ADR-001 adopts "Work" as the umbrella, moving the index from `/projects` to
`/work`. The detail route `/work/<slug>` already exists. The PRD constraint and
ADR-001's risk mitigation both suggested a redirect/alias from `/projects` to
preserve backward-compatible URLs. The `/projects` index, however, was added only
days ago (it is not yet linked externally), so there are effectively no inbound
links or bookmarks to preserve. The Netlify build already runs `linkinator`
across `dist`, failing the deploy on any broken internal link.

## Decision

Perform a **hard rename with no redirect**. The index page moves to
`src/pages/work/index.astro`; the old `/projects` URL is not served and no
Netlify redirect is added. All internal references to `/projects` are updated in
the same change (notably the "See all projects" link in `CaseStudies.astro`).
`linkinator` in the build is the safety net for any missed internal reference.

This decision **supersedes the PRD constraint** "Maintain backward-compatible
URLs (alias/redirect the old projects path)" and ADR-001's redirect mitigation,
on the grounds that there is no URL history worth preserving on a days-old route.

## Alternatives Considered

### Alternative 1: 301 redirect `/projects` → `/work`

- **Description**: Add a Netlify permanent redirect.
- **Pros**: Survives any stray inbound link; canonical SEO transfer.
- **Cons**: Carries a redirect indefinitely for a route with no real history.
- **Why rejected**: No inbound links exist to protect; owner chose the clean
  rename.

### Alternative 2: Serve both `/projects` and `/work` (alias)

- **Description**: Render the index at both paths.
- **Pros**: No broken links.
- **Cons**: Duplicate-content URLs and a split canonical for identical content.
- **Why rejected**: Two live URLs for one page is worse than a clean single URL.

## Consequences

### Positive

- One canonical URL for the work index; no lingering redirect config.

### Negative

- Any pre-existing `/projects` link (none known) would 404.

### Risks

- A missed internal `/projects` reference ships broken. Mitigation: `linkinator`
  in the Netlify build fails the deploy on broken internal links.

## Implementation Notes

- Move `src/pages/projects.astro` → `src/pages/work/index.astro` (keep the
  company-grouping logic).
- Update the `/projects` link in `src/components/CaseStudies.astro` to `/work`
  and relabel it "See all work".
- No change to `netlify.toml`.
