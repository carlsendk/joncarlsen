# ADR-003: Draft-gated placeholders via a sentinel and a render guard

## Status

Accepted

## Date

2026-06-10

## Context

The owner wants to stage high-value missing figures in context (for example
"reduced operational cost by ... at Scrive") and fill them later, without the
unfinished text ever appearing on the live site (PRD, ADR-002). The owner chose
draft-gated TODO markers over keeping placeholders out of the content entirely.
The site is static, so the guard must work at build time with no client code.

## Decision

Use a sentinel marker plus a render guard, and verify against the built output:

- A placeholder is written inline in a `cv.ts` array item using the sentinel
  `[TODO: ...]`, for example `"Reduced cloud spend by [TODO: % YoY] at Scrive"`.
- A small exported guard, `isReady(text)` (true when the text does not contain
  `[TODO`), is applied by the components that render array items (role `bullets`,
  `impact`, `credentials`, `talks`). Any item that is not ready is filtered out,
  so it never renders. Single-string spine fields (summary, scope) hold only
  complete real sentences; figure drafts go in array items.
- The placeholder leak check runs against the built HTML (`dist/**/*.html`),
  expecting zero occurrences of the sentinel and of `lorem`/`placeholder`. The
  source-level no-placeholder gate is replaced by this built-output gate, because
  the sentinel is now an intentional, gated marker in `cv.ts`.
- Every open `[TODO]` is also listed in `content-gaps.md` so the gaps are tracked
  in one place.

## Alternatives Considered

### Alternative 1: No inline placeholders (gaps only in the checklist)

- **Description**: Rendered fields hold only complete sentences; gaps live solely
  in the checklist and comments.
- **Pros**: Simplest; no render guard.
- **Cons**: The owner cannot draft a figure in its real sentence context.
- **Why rejected**: The owner chose in-context draft markers.

### Alternative 2: Inline placeholders with no guard

- **Description**: Write `[TODO]` text directly in rendered fields.
- **Pros**: Trivial.
- **Cons**: The unfinished text leaks straight to the live site.
- **Why rejected**: Violates the no-placeholder-on-site rule.

## Consequences

### Positive

- The owner stages figures in context safely; nothing unfinished reaches the site.
- The built-output gate is a hard guarantee against leaks.

### Negative

- A small render-guard helper and a filter in the array-rendering components.
- The placeholder gate moves from source to built output, a change to the existing
  verification step.

### Risks

- A component forgets to apply the guard. Mitigation: the built-output gate fails
  the build if any sentinel reaches `dist/`.
