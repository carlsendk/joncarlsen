# ADR-005: Style with Tailwind CSS

## Status

Accepted

## Date

2026-06-09

## Context

The PRD requires a mobile-first, fast-loading page with clear visual hierarchy
and good accessibility (PRD: UX, Technical Constraints). Styling must support
rapid, consistent responsive layout work while keeping shipped CSS small to
protect load time.

## Decision

Use Tailwind CSS via its Astro integration. Build responsive, mobile-first
layouts with utility classes. Tailwind's build step removes unused classes, so
the shipped CSS stays minimal.

## Alternatives Considered

### Alternative 1: Plain scoped CSS (Astro built-in)

- **Description**: Per-component scoped `<style>` blocks.
- **Pros**: Zero extra dependencies; fully hand-crafted control.
- **Cons**: Slower to build responsive layouts; more boilerplate for breakpoints
  and consistent spacing.
- **Why rejected**: Tailwind delivers responsive, consistent styling faster with
  comparable shipped-CSS size after purge.

### Alternative 2: Lightweight CSS framework (Pico / Open Props)

- **Description**: Classless or token-based CSS defaults.
- **Pros**: Instant reasonable defaults with little effort.
- **Cons**: Less control over a distinctive, polished look — which matters for a
  job-hunting site.
- **Why rejected**: Insufficient design control for a site whose job is to
  impress recruiters.

## Consequences

### Positive

- Fast, consistent, mobile-first responsive development.
- Small purged CSS output supports the load-speed goal.

### Negative

- Adds Tailwind as a build dependency and utility-class verbosity in markup.

### Risks

- Risk: inconsistent spacing/typography without discipline. Mitigation: rely on
  Tailwind's default scale and a small set of shared design tokens.

## Implementation Notes

- Add Tailwind via the Astro integration; configure content globs so unused
  styles are purged from the production build.
