# ADR-003: The work collection is the canonical source of impact and skills

## Status

Accepted

## Date

2026-06-10

## Context

The site has two parallel content models: `cvData` (a typed TypeScript object in
`src/data/cv.ts`, driving `/` and `/cv`) and the `work` markdown collection
(driving `/projects` and `/work/<slug>`). Impact numbers exist in three places
today: `cvData.impact` (a hand-authored `Highlight[]`), prose inside each role's
bullets, and `work.metrics[]` frontmatter (rendered as pills on cards and the
case-study header).

ADR-001/002 (product) chose the role bullet as the connective unit and an
auto-aggregated `/impact` page, but left the canonical location of the impact
figure ambiguous. During technical clarification the owner resolved it: **impact
and skills are set on the work case study**; roles carry a job description plus
descriptive bullets of work done, and notable bullets link to a work entry. The
hierarchy is Role → descriptive bullet → links to → Work → which owns impact and
skills.

This supersedes ADR-001's implementation note that "the impact number is part of
the bullet". The connective role of the bullet (role → work link) stands; the
metric simply lives on the work, not the bullet.

## Decision

Treat the **`work` collection as the single canonical source** of impact
(`metrics[]`) and skills (`skills[]`). Both fields already exist in the schema
(`src/content.config.ts`), so no schema change is required.

- **`cvData.impact` (`Highlight[]`) is removed** from `CvData`, along with the
  `Highlight` interface. Its figures are migrated onto the matching work entries'
  `metrics[]` (most already present, e.g. "50,000 datapoints/s",
  "3 to 20 person department"); migration is mostly verification.
- **`Role.bullets` becomes `Bullet[]`** where the bullet is a description with an
  optional work link, carrying **no metric**:

```ts
export interface Bullet {
  text: string;    // description of work done, rendered on /cv
  work?: string;   // slug into the work collection when a case study backs it
}
```

- **`/impact`, home, and `/cv`** all derive their numbers from `work.metrics[]`
  (see ADR-004 for the derivation rules).

Because every impact figure lives on a work entry, and every work entry renders
its own page, every impact line has a destination — there are no metric-only
bullets to special-case.

## Alternatives Considered

### Alternative 1: Bullet carries the canonical metric (prior draft)

- **Description**: Put `metric` on the bullet (`{ text, metric?, work? }`) as the
  source; derive `/impact` from bullets.
- **Pros**: Allows a metric with no backing case study.
- **Cons**: Duplicates the number against the bullet's own prose; on `/cv` the
  full timeline already shows the bullet text, so a derived Impact section would
  repeat the same sentence; the owner placed impact on the work, not the bullet.
- **Why rejected**: Owner direction; work-as-source removes the `/cv`
  duplication because bullets are descriptions and metrics are separate.

### Alternative 2: Keep both bullet metrics and work metrics with dedup

- **Description**: Allow metrics on bullets and work, merge for `/impact`.
- **Pros**: Maximum flexibility.
- **Cons**: Two sources and dedup logic for a seven-file site.
- **Why rejected**: Gold-plating; violates YAGNI.

## Consequences

### Positive

- One source per concern: impact and skills on the work; descriptions on the
  bullet. No triple-authored `cvData.impact`.
- `/cv` shows a metric band (from work) and descriptive bullets (from roles)
  without repetition.
- `work.metrics[]`/`skills[]` already feed the case-study card and header, so the
  same source powers every surface — nothing duplicated.

### Negative

- `Role.bullets` shape change (`string[]` → `Bullet[]`) touches `Timeline.astro`
  and all eight roles' bullet data in one migration.
- An impact figure that lacks a case study requires creating a (possibly
  unfeatured) work entry to host it.

### Risks

- Migration could drop a former `cvData.impact` figure. Mitigation: an explicit
  before/after check mapping each figure to a work entry's `metrics[]`.

## Implementation Notes

- `src/data/cv.ts`: add `Bullet`; change `Role.bullets` to `Bullet[]`; migrate all
  eight roles' bullets to objects; add `work` slugs to notable bullets; remove
  `Highlight` and `CvData.impact`.
- `src/content.config.ts`: unchanged.
- Impact derivation lives in a shared module that queries the collection (ADR-004).
