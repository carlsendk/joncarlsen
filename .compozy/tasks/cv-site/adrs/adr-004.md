# ADR-004: Host on GitHub Pages with push-to-deploy via GitHub Actions

## Status

Superseded by [ADR-007](adr-007.md) — hosting moved to Netlify (2026-06-09).

Accepted

## Date

2026-06-09

## Context

The site is a static Astro build (ADR-003) that must be publicly reachable at a
URL the owner shares in applications (PRD: Goals, Success Metrics). The
repository already has a GitHub remote (`git@github.com:carlsendk/joncarlsen.git`),
and the owner's prior site was GitHub-Pages-based. Hosting should be free, require
no new accounts, and deploy automatically when content changes.

## Decision

Host on GitHub Pages. A GitHub Actions workflow builds the Astro site and
publishes the static output to Pages on every push to the default branch. The
quality gate (ADR — see TechSpec Testing Approach) runs in the same workflow and
blocks deploy on failure.

## Alternatives Considered

### Alternative 1: Cloudflare Pages / Netlify

- **Description**: A third-party static host connected to the Git repo.
- **Pros**: Built-in deploy previews; very easy custom-domain setup; global CDN.
- **Cons**: Requires a new account and external service dependency.
- **Why rejected**: GitHub Pages meets the requirements with no new account and
  matches the owner's existing setup; previews are unnecessary for a solo
  one-page site.

### Alternative 2: Firebase Hosting

- **Description**: Google's static hosting with CDN.
- **Pros**: Fast CDN; an existing firebase-deploy skill is available locally.
- **Cons**: Requires a Firebase project and more configuration; another service
  to manage.
- **Why rejected**: More setup than needed; GitHub Pages is simpler and
  sufficient.

## Consequences

### Positive

- Free, no new accounts, deploys on push.
- Co-located with the source repo; one place to manage.

### Negative

- No built-in deploy previews (acceptable for a single-page solo site).
- URL path depends on repo/domain configuration (see Risks).

### Risks

- Risk: base-path misconfiguration breaks asset and PDF links. The repo is named
  `joncarlsen` (not `carlsendk.github.io`), so by default Pages serves a
  **project page** at `carlsendk.github.io/joncarlsen`, requiring Astro
  `base: '/joncarlsen'`. A custom domain or a `carlsendk.github.io` user repo
  requires `base: '/'`. Mitigation: resolve the domain/URL open question before
  build and set Astro `site`/`base` accordingly (flagged as a Technical
  Dependency in the TechSpec).
- Risk: GitHub Pages must be enabled for the repo with the Actions source.
  Mitigation: enable Pages (source: GitHub Actions) as a prerequisite step.

## Implementation Notes

- Workflow: build with Astro, upload the `dist/` artifact, deploy via the
  official Pages deploy action.
- Set `site` and `base` in `astro.config` per the resolved domain decision.
