# ADR-003: Long-tail disclosure via always-rendered DOM + class toggle, default expanded

## Status

Accepted

## Date

2026-06-11

## Context

PRD Core Feature 4 requires collapsing only the long tail (earlier roles, lists
over a length threshold) while keeping `/cv` a complete overview: disclosed
content must remain rendered, indexable, and printed in full. The build gates on
Lighthouse (performance ≥ 0.90, accessibility ≥ 0.95; `netlify.toml`).

The site is near-zero-JS today: one inline theme flash guard and one bundled
theme-toggle script (`is:inline` for the pre-paint guard, a deferred IIFE
`<script>` for the click handler). There is **no** existing disclosure UI,
`<details>`, or `aria-expanded` pattern. The print stylesheet already forces all
content visible by cancelling `.reveal` (`opacity:1 !important`), which is the
precedent for "print shows everything."

A native `<details>`/`<summary>` toggle is the zero-JS option, but a **closed**
`<details>` cannot be reliably forced open via print CSS across browsers — its
content would risk being dropped from print, violating the completeness criterion.

## Decision

Collapse long-tail content with an **always-rendered DOM + class-toggle** pattern,
defaulting to **expanded** in the server-rendered HTML:

1. **SSR renders the full content, expanded.** No content is conditionally omitted;
   every role and list item is in the HTML.
2. **A bundled, deferred IIFE `<script>` collapses the tail on load** by adding a
   collapse class to the overflow group and injecting/activating a real `<button>`
   with `aria-expanded`. Clicking toggles the class and `aria-expanded`.
3. **Print and no-JS show everything.** A `@media print` rule (and the absence of
   JS) leaves content expanded; the collapse class is overridden in print exactly
   like the existing `.reveal` cancel.
4. **Scope of collapse:** the experience timeline keeps the N most-recent roles
   visible and hides the remainder behind a single bulk "Show earlier roles (N)"
   expander — **never per-role toggles and never a slice/limit** (all roles stay
   rendered). The same reusable collapse wrapper applies to any list exceeding the
   length threshold; at current content counts only the timeline engages it (see
   TechSpec).

**Asymmetry, stated deliberately:** native `<details>` IS used for the *mobile nav
dropdown* (ADR-002), because the nav is `display:none` in print so its print
behavior is moot, and it benefits from zero-JS. It is **not** used for *content*
collapse, because content must print expanded. A future reader must not
"simplify" the content collapse into `<details>` — doing so breaks print.

This shares the site's progressive-enhancement posture: the page is complete and
correct with zero JS; the two new scripts (this collapse + the ADR-002 scroll-spy)
only *enhance*. The user has approved adding both, given they cannot regress no-JS,
print, or SEO and are not expected to threaten the Lighthouse budget.

## Alternatives Considered

### Alternative 1: Native `<details>`/`<summary>` for content

- **Description**: Wrap the long tail in `<details>`; the summary is the expander.
- **Pros**: Zero JavaScript for the toggle; keyboard-accessible by default.
- **Cons**: A closed `<details>` cannot be reliably forced open in print CSS across
  browsers, risking dropped content in the printed/PDF CV; default-closed also
  hides content from some extraction contexts.
- **Why rejected**: Directly endangers the "print shows everything" success
  criterion, which is a hard requirement.

### Alternative 2: CSS-only checkbox/`:target` hack

- **Description**: Toggle via a hidden checkbox + sibling selector, no JS.
- **Pros**: Zero JavaScript.
- **Cons**: Default state lives in markup; print-forcing is as awkward as
  `<details>`; weaker semantics/ARIA; fragile focus handling.
- **Why rejected**: More fragile than a small script while solving nothing the
  class-toggle doesn't, and still print-hostile.

## Consequences

### Positive

- Completeness guaranteed: content is always in the DOM, so SEO, no-JS, and print
  all get the full CV; print reuses the established force-visible idiom.
- Matches the existing bundled-IIFE script convention; no new framework.
- One reusable collapse wrapper covers the timeline tail and any over-length list.

### Negative

- Adds a second progressive-enhancement script; total site JS roughly triples
  (from one toggle to three small scripts).
- A brief post-load collapse occurs on the tail as JS runs; must be below the fold
  to avoid layout-shift cost.

### Risks

- **Cumulative Layout Shift against the 0.90 perf budget.** *Mitigation*: collapse
  only below-the-fold content (the earlier-roles tail), so the shift is outside the
  viewport and does not count toward CLS; verify in the Lighthouse report.
- **`.reveal` animation stuck at `opacity:0` on expand.** Content revealed by the
  toggle could remain faded if the view-timeline animation never fires on a
  display-toggled element. *Mitigation*: ensure expanded content resolves to full
  opacity (e.g. the collapse class governs height/visibility, not the `.reveal`
  opacity, or the expander clears the reveal state); verify on expand.
- **A11y regressions.** *Mitigation*: real `<button>`, correct `aria-expanded` and
  controlled-region association, keyboard operable; keep Lighthouse a11y ≥ 0.95.

## Implementation Notes

- One small collapse module wired by a shared `data-` hook or component; default N
  (recent roles) and the list length threshold are constants defined in the
  TechSpec and tunable.
- Print rule extends the existing `@media print` block to neutralize the collapse
  class, mirroring the `.reveal` cancel.
