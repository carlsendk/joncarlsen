# ADR-002: In-page navigation as a right-margin sticky rail with progressive-enhancement scroll-spy

## Status

Accepted

## Date

2026-06-11

## Context

PRD Core Feature 3 calls for a sticky in-page navigation listing ~6 curated
groups, with current-section highlighting, that coordinates with the existing
sticky header (`#site-header`, `sticky top-0 z-40`, ≈4rem) and collapses to a
dropdown on small screens.

The `/cv` layout is a centered `max-w-2xl` column (~672px) with wide empty margins
on desktop (`html` already sets `scroll-padding-top: 4.5rem` to clear the header
for anchor landings; `src/styles/global.css`). The print stylesheet already hides
`nav { display: none !important }` and cancels `.reveal`.

The shape of the nav determines whether a second sticky element stacks below the
header (forcing a `scroll-padding-top` recompute and consuming vertical space) or
lives outside the reading column.

## Decision

Implement the in-page nav as a single new `CvNav.astro` component rendering a
`<nav aria-label="On this page">` with ~6 anchor links, one per curated group,
each targeting the `id` of the group's first section.

- **Desktop (≥ the breakpoint where margin exists, `lg`):** a vertical "On this
  page" rail pinned in the **right margin** (`position: sticky`), beside — not
  above — the column. It consumes zero vertical space and does **not** stack under
  the header, so `scroll-padding-top` stays as-is.
- **Small screens:** the rail collapses to an openable dropdown (a native
  `<details>`/`<summary>` "Jump to…" disclosure), not the full rail and not hidden.
- **Current-section highlighting:** a bundled, deferred IIFE `<script>` uses
  `IntersectionObserver` to set `aria-current="true"` on the active group link as
  the reader scrolls. This is **pure progressive enhancement** — the anchor links
  work without JavaScript; only the highlight requires it.

Anchor targets reuse stable section `id`s (added to each section's `<section>`
wrapper; see ADR-004 wiring). The nav is a `<nav>` element, so the existing print
rule hides it automatically.

## Alternatives Considered

### Alternative 1: Horizontal sticky sub-bar under the header

- **Description**: A second sticky bar of ~6 chips directly below `#site-header`.
- **Pros**: Always visible; familiar pattern; trivially responsive.
- **Cons**: Permanently consumes ~3rem of vertical sticky chrome on every screen;
  stacks under the header, forcing `scroll-padding-top` to be recomputed to clear
  header + bar and re-verified in both themes.
- **Why rejected**: Pays a permanent vertical cost and reintroduces the
  double-sticky-offset problem the margin rail avoids entirely.

### Alternative 2: Dropdown "Jump to…" menu on all screen sizes

- **Description**: A single compact disclosure button on every breakpoint.
- **Pros**: Least chrome; simplest layout.
- **Cons**: The section list is hidden until opened, so it is weak as persistent
  wayfinding — the reader cannot see the page's shape at a glance.
- **Why rejected**: Undersells the navigability goal on desktop, where there is
  ample room for an always-visible rail. (Retained as the small-screen form only.)

## Consequences

### Positive

- Zero vertical space cost on desktop; the reading column is untouched.
- No `scroll-padding-top` rework — the rail does not stack under the header.
- Always-visible wayfinding on desktop; compact dropdown on mobile.
- Print-safe and no-JS-safe by construction (anchors are plain links; `<nav>` is
  already print-hidden; highlight is enhancement-only).

### Negative

- The rail only appears where margin exists (`lg+`); below that readers rely on
  the dropdown. Acceptable and expected.
- Adds one `IntersectionObserver` script to the site's JS surface (see ADR-003 for
  the combined progressive-enhancement posture and the Lighthouse-gate rationale).

### Risks

- **Rail overlaps content at intermediate widths.** *Mitigation*: show the rail
  only at `lg+` where the margin is wide enough; use the dropdown below that.
- **Scroll-spy mis-highlights near section boundaries.** *Mitigation*: observe all
  sections, map each to its group, and pick the topmost intersecting section;
  keyboard focus and `:target` still work without the observer.

## Implementation Notes

- Group → anchor mapping and the six labels are defined in the TechSpec Core
  Interfaces (`navGroups`). Exact labels are tunable.
- The rail and dropdown render the same `navGroups` data; only presentation
  differs by breakpoint.
- Verify anchor landings clear the header in both themes after wiring.
